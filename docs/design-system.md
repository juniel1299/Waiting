# 다음자리 디자인 규칙 (2026-11-25, 확장 1단계)

참고: 토스의 **분명한 정보 위계**(화면마다 한 가지 주제, 큰 제목 → 요약 → 한 가지 주요 행동)와 당근의 **친근한 카드**(둥근 모서리, 넉넉한 안쪽 여백, 제목·보조 정보 순서). 새 색·글꼴을 들이지 않고 지금 토큰(`frontend/src/app/globals.css`)을 정리해 쓴다.

## 위계

1. 화면 제목 `h1` 하나 → 요약 한 줄(`.meta`) → 주요 행동 버튼 하나(채운 버튼) → 목록·카드.
2. 한 화면에 채운 버튼은 하나. 나머지 행동은 테두리 버튼(`.secondary`)·링크.
3. 상태는 **색 + 글자**(배지 `승인 대기`·`읽지 않음`·`모임 운영자`). 색만으로 구분하지 않는다.

## 토큰

| 구분 | 값 |
|---|---|
| 색 | 강조 `--accent`, 성공 `--ok`, 위험 `--danger`, 보조 글 `--muted`, 선 `--line`, 강조 바탕 `--surface-soft` (어두운 테마는 기존 대응) |
| 글자 | 본문 16px·줄 간격 1.5, 보조 14px(`.meta`), 제목 `h1` 24px·`h2` 18px |
| 여백 | 4의 배수: `--space-1` 4 · `--space-2` 8 · `--space-3` 12 · `--space-4` 16 · `--space-6` 24 |
| 모서리 | 카드 `--radius` 12px, 메뉴 항목·버튼 8px, 배지 원형 |
| 높이 | 버튼·입력·선택 최소 44px (터치 대상) |
| 움직임 | 모든 전환 `--motion` 180ms, `prefers-reduced-motion` 이면 이동·애니메이션 끔 |

## 구성 요소

- **카드:** 1px 선, 반경 12px, 안쪽 16px. 제목(링크) → 보조 정보 한 줄 → 배지. 제목 링크의 덮개가 카드 전체를 상세 이동 영역으로 만들고, 카드 안 버튼은 `.card-actions` 로 덮개 위에 둔다(덮개 아래 버튼은 눌리지 않음 — 커뮤니티 4단계에서 겪은 버그).
- **버튼:** 기본(채움)·`.secondary`(테두리)·`.danger`(위험). 상태: hover·`focus-visible`(2px 강조 테두리)·active(눌림)·loading(글자 바꿈 + 비활성)·disabled.
- **입력:** 위에 `label`, 오류는 `role=alert`, 길이 제한은 `maxLength` 와 서버 검증 둘 다.
- **메뉴:** 데스크톱(≥ 900px)은 왼쪽 사이드바(접기·펼치기, 접힘은 기억), 모바일은 서랍. 현재 화면의 묶음은 펼치고 항목은 `aria-current="page"`(강조 바탕 + 왼쪽 선 + 굵게). 서랍은 `role=dialog`, 열면 첫 항목에 초점, Esc·바깥·선택으로 닫으면 `메뉴` 버튼으로 초점 복귀, 열린 동안 본문은 `inert`.
- **토스트:** 오른쪽 아래, `role=status`, 6초 뒤 사라짐, 최대 3개.
- **화면 상태:** 불러오는 중 · 빈 목록(다음 행동 링크) · 권한 없음(다시 시도 없이 안내 + 돌아갈 링크) · 삭제됨 · 오류(다시 시도 버튼).

## 1단계에서 적용한 화면

- 틀: 모든 로그인 화면의 위 막대·사이드바·서랍(`frontend/src/components/Shell.tsx`).
- 목록·상세·모임: 카드·입력 토큰(반경 12px·안쪽 16px·44px), 모임 소개의 모임 안 메뉴(공지·게시판·회원·권한 관리), 권한 관리 탭의 역할별 할 수 있는 일 표.
- 운영: 서비스 권한 관리(권한표·계정별 역할·변경 기록).

나머지 화면은 같은 공통 CSS(버튼·카드·배지)를 이미 쓰고 있어, 단계마다 손대는 화면부터 위계 규칙을 맞춘다.
