# 채팅 이전 기록 조회 (2026-11-27)

6단계 모임 채팅은 최근 50건만 보였다. 위쪽 '이전 메시지 더 보기'로 과거 기록을 거꾸로 읽게 했다.

## API

- `GET /api/clubs/{id}/chat` (처음): 최근 50건 + 이어 받기 `cursor` + **`hasMoreBefore`**(더 오래된 메시지가 있는지).
- `GET /api/clubs/{id}/chat?after={cursor}` (이어 받기, 기존): seq 가 큰 변경(새 메시지·삭제)과 다음 `cursor`.
- `GET /api/clubs/{id}/chat?before={메시지 id}&limit={1~100, 기본 50}` (**새로 추가**): 그 id 보다 오래된 메시지를 최신 쪽부터 `limit` 건, id 오름차순. 응답은 `{items, hasMore}` 이고 **`cursor` 가 없다**: 이전 기록을 읽어도 이어 받기 위치(읽음 위치)가 뒤로 가지 않는다. `after` 와 `before` 를 함께 주면 400.
- 커서: 과거 방향은 메시지 id(표시 순서), 새 방향은 변경 순번 seq. 화면은 둘 다 id 로 합치므로(같은 id 는 새 상태로 덮어씀) 중복이 없고, 과거 페이지는 처음 50건보다 작은 id 만, 이어 받기는 처음 cursor 이후 변경을 모두 받으니 빠짐도 없다.
- 권한·표시: 기존과 같다. 승인된 모임의 지금 회원만(요청마다 재확인 → 모임 탈퇴 직후 403), 계정 정지·탈퇴 직후는 세션이 무효라 401. 지운 메시지는 과거 페이지에서도 내용 없이 삭제 표시.

## 화면

- 목록 위 '이전 메시지 더 보기' → 불러오는 중(누를 수 없음) → 실패하면 "이전 메시지를 불러오지 못했어요." + '다시 시도' → 끝까지 읽으면 "처음 메시지예요.".
- **보던 위치 유지:** 붙이기 직전 `scrollHeight·scrollTop` 을 기억했다가, 그린 직후(`useLayoutEffect`) 늘어난 높이만큼 내려 같은 메시지가 같은 자리에 남는다(e2e 에서 위치 차이 4px 미만 확인).
- **새 메시지:** 맨 아래 근처(120px 이내)면 따라 내려가고, 위를 보고 있으면 스크롤을 건드리지 않고 '새 메시지 N개 ↓'(내 메시지·과거 기록은 세지 않음). 누르면 맨 아래로. 내가 보내면 맨 아래로 간다.
- 3초 이어 받기(화면이 보일 때만)는 그대로고, 이전 기록 조회와 서로의 결과를 하나의 목록 기준으로 id 병합한다.

## 테스트 (실제 PostgreSQL)

- `ClubChatHistoryTests`(3): 120건에서 과거 2쪽을 읽는 사이사이 새 메시지·이어 받기를 끼워도 합치면 전체와 같음, 과거 응답에 `cursor` 없음 / 삭제 표시·limit(10→5건 남음, 500→100 으로 제한, 7)·after+before 400 / 모임 탈퇴 직후 403, 계정 정지·탈퇴 직후 401. 구현 전 2개 실패 확인(권한 테스트는 기존 동작으로 이미 통과).
- `ClubChatConcurrencyTests` 추가(3회): 120건을 20건씩 거꾸로 읽는 동안 3명이 30건을 동시에 보내도 처음+과거+이어 받기 합 = 전체 150건. 구현 전 실패 확인.
- 프런트 단위(`chat.test.mjs`): 스크롤 앵커 계산, 맨 아래 판정, 새로 붙은 메시지 수(과거·내 메시지 제외). 구현 전 실패 확인.
- e2e(`chat-history.spec.ts` 2): 120건 → 최근 50건 → 과거 2쪽(보던 메시지 위치 유지) → 위를 보는 동안 새 메시지 안내·스크롤 그대로 → 안내 누르면 새 메시지가 보이고 전체 121건(중복 없음) / 과거 조회 실패 뒤 다시 시도. e2e 는 구현 뒤 처음 실행.
- e2e 백엔드는 채팅 속도 제한을 넉넉히(`--daumjari.chat.max-per-window=1000`) 두어 120건을 빨리 넣는다(속도 제한 자체는 백엔드 테스트가 확인).
