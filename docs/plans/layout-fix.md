# 화면 깨짐·레이아웃 정리 (2026-11-27)

사용자가 공개 사이트에서 찾은 문제(날짜 입력 넘침, 버튼·메뉴 높이 불일치, 공개 프로필·모임 상세·회차 관리 배치)를 공통 스타일과 화면별 배치로 나눠 고쳤다. 공통 입력·버튼 컴포넌트는 따로 없고 `frontend/src/app/globals.css` 의 요소 규칙(`button`, `input`, `.button-link` 등)이 공통 컴포넌트 역할을 한다.

## 원인과 수정 위치

| 문제 | 재현·원인 | 수정 |
|---|---|---|
| 날짜 입력이 테두리 밖으로 (전체 회차·내가 만든 회차·누적 사용량) | 세 화면이 같은 `.search-row`(flex, 칸 기본 너비 140px)를 쓴다. 날짜 입력은 브라우저가 정한 고유 최소 너비(날짜 글자 + 달력 버튼)가 있어 칸이 그보다 좁으면 넘친다. 이 Mac 의 Chromium(한국어, 값 입력 상태)에서는 375px 에서 칸 149px 에 겨우 들어가 글자와 달력 버튼이 붙어 있었고 넘치지는 않았다. Safari 는 날짜 입력의 고유 너비가 더 크고 `width` 를 덜 따르는 것으로 알려져 있어(사용자 환경으로 추정) 같은 구조에서 넘친다 — **Safari 재현은 하지 못함** | 공통: 날짜·시간 입력 `width:100%`·`min-width:0`·높이 44px, 검색 행 날짜 칸 기본 너비 180px, 599px 이하에서는 날짜 칸마다 한 줄(시작일·종료일 짝이 다른 칸과 섞이지 않게), iOS Safari 에서만 기본 모양을 꺼 칸 너비를 따르게(`@supports (-webkit-touch-callout: none)`), 날짜 글자 왼쪽 정렬 |
| 같은 줄 버튼·입력 높이가 달라 보임 | `line-height: normal` 이 글꼴(Apple SD Gothic Neo·Noto Sans KR)마다 달라 버튼·입력·선택의 글자 높이가 제각각. 링크 버튼(`.button-link`: 글쓰기·모임 만들기 신청·수정)은 `min-height` 로 늘어난 높이에서 글자가 위로 붙었다. 사진 올리기 라벨 버튼은 padding·모서리가 달랐다(8px 16px·8px). 메뉴 묶음·항목은 40px | 공통: 버튼·링크 버튼·라벨 버튼을 같은 상자(inline-flex 가운데, 테두리 1px, padding 8px 12px, `line-height 1.25`, 최소 44px)로. 입력·선택도 `line-height 1.25`. 메뉴 묶음·항목 44px. 로딩(`.loading`)·비활성은 투명도·커서만 바꿔 크기가 그대로 |
| 선택창이 입력보다 낮음 (Safari·iPhone) | WebKit(iPhone 17 Pro 에뮬레이션)에서 재현: 기본 모양의 `select` 에는 `min-height` 가 적용되지 않아 약 22px 로 그려져, 같은 줄 44px 입력·버튼과 높이가 달랐다(Chromium 에서는 44px 이라 보이지 않던 문제) | 공통: `select` 기본 모양을 끄고 화살표를 SVG 로 그려 높이 44px |
| 검색 행 정렬·줄바꿈 | `.search-row` 에 세로 정렬 기준이 없고 `.actions` 는 줄바꿈이 없었다 | 공통: `.search-row` 아래선 정렬, `.actions` 줄바꿈·가운데 정렬 |
| 모임 목록 검색 | 검색 버튼만 있어 게시판·회차 검색과 모양이 달랐다 | `ClubList.tsx`: 초기화 버튼(검색어 없으면 비활성, 주소 `/clubs` 로) |
| 모임 만들기 신청 라디오가 세로 | 라디오 라벨이 `fieldset.field`(세로 flex)의 직접 자식이고 `.form label` 이 세로 배치를 강제 | `ClubForm.tsx`: `.choices` 로 감싸 가로·줄바꿈, `label.choice` 44px 누름 영역(라벨 클릭·방향키 그대로) |
| 공개 프로필 | 닉네임·소개·태그가 한 카드에 섞여 있고 태그가 없으면 제목도 없었다 | `profiles/[id]/Detail.tsx`: 아바타(닉네임 첫 글자)·닉네임 머리, 자기소개·관심 태그 각각 구역, 비어 있으면 안내. 긴 닉네임·소개는 `overflow-wrap:anywhere`. 480px 이하 세로. 공개 항목은 그대로(닉네임·소개·태그). 서버가 주는 공개 활동 정보는 없어 활동 구역은 만들지 않았다 |
| 모임 상세 | 이름·즐겨찾기·정보·내 역할·소개·버튼이 위에서 아래로 섞여 있고, 모임 안 메뉴가 정보와 소개 사이에 끼어 있었다 | `ClubDetail.tsx`: 머리 상자(이름·즐겨찾기, 가입 상태 배지, 승인 단계, 활동 정보, 버튼 줄) → 모임 안 메뉴 띠(좁으면 띠 안에서 가로 스크롤) → 소개. 버튼 순서 고정(가입/수정/신청 취소/탈퇴, 삭제는 오른쪽 끝) |
| 회차 관리 | 정원 변경 입력과 버튼이 `.actions`(가운데 정렬) 안에서 라벨 높이만큼 어긋나 버튼이 68px 로 늘어났다. 수정 링크·명단·삭제가 구분 없이 이어졌다 | `manage/Manage.tsx`: 회차 정보(일시·장소·모집 상태 + 정원·확정·대기 카드) / 정원 변경(입력·버튼 아래선 정렬) / 확정 명단(표는 가로 스크롤 상자) / 관리 작업(수정, 점선 아래 삭제와 안내). 삭제 확인 창은 그대로. 대기 명단은 API 가 주지 않아 인원만 보인다 |

모임 안 하위 화면(게시판·공지·채팅·사진첩·회원)은 이번에 바꾸지 않았다(각 화면 위 '← 모임 소개' 링크 그대로).

## 확인 환경

- **Chromium(Playwright, 이 Mac, 한국어)**: 데스크톱 1280, 모바일 390·375(320 은 날짜만). 화면 캡처와 e2e.
- **WebKit(Safari 엔진, Playwright WebKit 27.2) + iPhone 17 Pro 에뮬레이션**(사용자 허락 뒤 설치, 2026-11-27): 변경 전(공개 사이트, 데모 체험)·변경 후(로컬) 회차 목록 검색과 새 e2e 전체(`E2E_WEBKIT=1`, 22개 = Chromium 11 + WebKit 11 통과). 변경 전 공개 사이트에서 선택창이 약 22px 로 낮은 것을 재현했다. **날짜 입력이 상자 밖으로 나가는 것은 WebKit 에뮬레이션에서도 재현되지 않았다**(402px 에서 날짜 칸 162px 안에 들어감).
- **실제 iPhone(사용자는 iPhone 18 Pro Safari 에서 발견): 확인 못 함.** macOS 의 WebKit 은 iOS 의 날짜 입력 모양(`-webkit-touch-callout` 지원 등)을 그대로 재현하지 않는다(`CSS.supports('-webkit-touch-callout','none')` 가 false). iOS 전용 규칙은 알려진 원인(고유 너비·가운데 정렬)에 대한 방어 규칙이며, 배포 뒤 실제 iPhone 에서 확인이 필요하다(아래 절차).
- 데모 체험·비회원 화면은 공통 스타일만 바뀌었다.

## 테스트

- 새 e2e `frontend/e2e/layout.spec.ts`(11): 날짜 입력이 칸·검색 상자 안(1280·390·375, 값의 글자 넘침 없음, 좁으면 세로), 포커스 표시, 버튼·링크 버튼·메뉴 44px와 같은 줄 높이·아래선, 모임 검색어 주소 유지·초기화, 라디오 가로 배치·라벨 클릭·방향키, 공개 프로필 구역·빈 안내·로그인 아이디 비노출, 긴 이름 모임 상세 영역 순서·가로 넘침 없음·버튼 높이, 회차 관리 구역·정원 입력/버튼 정렬·삭제 분리·확인 취소.
- 구현 뒤에 작성했고, 구현을 되돌린 코드로 돌려 11개 중 10개 실패를 확인했다(1280px 날짜 테스트는 원래도 통과).
- Safari 엔진으로도 돌리려면: `npx playwright install webkit` 뒤 `E2E_WEBKIT=1 npx playwright test e2e/layout.spec.ts` (평소 `npx playwright test` 는 Chromium 만).

## 남은 확인 (사용자)

1. iPhone Safari: 관리 > 전체 회차, 관리 > 사용량, 내 활동 > 내가 만든 회차에서 시작일·종료일을 눌러 날짜를 고른 뒤, 입력이 상자 안에 있고 값이 다 보이는지.
