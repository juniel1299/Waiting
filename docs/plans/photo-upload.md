# 사진 업로드 개선과 검증 (2026-11-27)

7단계 사진첩의 지원 범위·실제 업로드 경로(화면 → Vercel 프록시 → 백엔드)의 한도를 맞추고, 실패·취소·재시도를 다듬었다.

## 지원 범위

| 입력 | 처리 |
|---|---|
| JPEG(RGB)·PNG(투명 포함)·WebP | 받음. 바이트 시그니처로 판단(확장자·Content-Type 무시). EXIF 방향 반영 → 긴 변 1600px JPEG + 썸네일 400px, EXIF(위치 포함) 없음 |
| CMYK·YCCK JPEG(인쇄용) | **거부, 이유 안내** `PHOTO_CMYK_UNSUPPORTED`: SOF 표지의 색 성분 수(4)로 판별. JDK 기본 리더가 읽지 못해, 깨진 파일과 구분해 "RGB 로 저장해 올려 달라"고 안내 |
| HEIC·HEIF(아이폰 기본) | **거부, 변환 방법 안내**: 화면이 보내기 전에 막고(형식·확장자), 서버도 ftyp 브랜드로 판별해 `PHOTO_HEIC_UNSUPPORTED`. 안내: 아이폰 설정 > 카메라 > 포맷 > '높은 호환성', 또는 공유 시 JPEG 로 저장 |
| GIF·글자 파일·확장자만 바꾼 파일 | 거부 `PHOTO_INVALID` |
| 머리는 맞고 속이 깨진 파일 | 거부 `PHOTO_INVALID` |
| 4천만 픽셀 초과 | 디코드 전에 거부 `PHOTO_INVALID`(압축 폭탄 방지) |

## 크기 한도를 층마다 맞춤

| 층 | 한도 | 넘으면 |
|---|---|---|
| 화면(브라우저) | 한 번에 보내는 크기 **4MB**(`MAX_UPLOAD_BYTES`). 4MB 넘는 사진은 이 기기에서 긴 변 2400px JPEG(품질 0.9)로 줄여 보낸다. 줄여도 4MB 를 넘거나 원본이 30MB 를 넘으면 보내지 않고 안내 | 보내기 전에 안내 |
| Vercel 프록시 | 요청 본문 **4.5MB**([공식 문서](https://vercel.com/docs/functions/limitations), 2026-11-27 확인) | 413 — 본문이 JSON 이 아니라서 화면은 상태 코드로 "4MB 이하로 줄여 다시 올려 주세요" + '다시 시도' |
| 백엔드 | multipart `max-file-size` 5MB, 서비스 5MB(직접 호출용) | 413 `PHOTO_TOO_LARGE` |

화면을 거친 업로드는 늘 4MB 이하라 프록시 한도(4.5MB)에 걸리지 않는다. 백엔드 5MB 는 프록시 없이 부르는 경우의 마지막 방어선이다.

## 실패·취소·재시도

- 보내는 동안 파일 선택을 막고(중복 제출 방지, 코드에서도 한 번에 하나), '올리기 취소'로 요청을 끊을 수 있다.
- 실패하면 원인별 안내(크기·형식·연결)와 '다시 시도'(같은 파일로) 버튼.
- 서버 쪽 정합성: 저장 중 실패(예: 썸네일 저장 실패)는 사진 행·바이트를 같은 트랜잭션으로 되돌리고, 본문을 다 받기 전에 끊긴 요청은 아무것도 남기지 않는다(`ClubPhotoFailureTests`). 용량 집계(`stored_bytes` 합)는 사진 행에서 세므로 남는 것이 없다.

## 테스트 파일·에뮬레이션으로 확인한 것 (로컬, 실제 PostgreSQL)

- `ClubPhotoEdgeTests`(4): 6000×4000(24MP) 원본 → 1600×1067, 세로 3000×4000 → 1200×1600(EXIF 없음), EXIF 방향 8 → 세로로, 방향 3 → 180도(왼쪽 색 확인), CMYK JPEG·HEIC 머리 → 각각의 안내 코드, 머리만 맞고 속이 깨진 JPEG·반쯤 잘린 PNG 거부. CMYK·HEIC 는 구현 전 실패 확인, 나머지는 기존 동작을 확인하는 테스트(처음부터 통과).
- `ClubPhotoFailureTests`(2): 썸네일 저장 실패 주입 → 500, 사진 행·바이트 0 / 실제 소켓으로 본문 1/3 만 보내고 끊기 → 사진 행·용량 변화 없음. 둘 다 기존 동작 확인(처음부터 통과).
- 기존 `ClubPhotoApiTests`·`ClubPhotoQuotaTests`·`ClubPhotoConcurrencyTests`(동시 업로드 용량 상한) 다시 통과.
- 프런트 단위(`photo.test.mjs`): 4MB 기준, HEIC(형식·확장자 모두) 안내, 413·서버 거부·연결 실패 안내 구분. 구현 전 실패 확인.
- e2e(`photo-upload.spec.ts` 3): HEIC 는 요청 없이 안내 / 프록시 413(본문 text/plain) → 크기 안내 → 다시 시도로 올라감 / 보내는 중 선택 막힘 → 취소 → 새로 고쳐도 사진 없음. e2e 는 구현 뒤 처음 실행.
